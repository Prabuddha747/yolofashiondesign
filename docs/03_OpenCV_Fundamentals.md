## Goal

Teach classical computer vision, one operation at a time, on a real image
from this project's own dataset — not a generic stock photo — so every
result connects back to the fashion-detection problem this project is
actually solving.

## Pipeline (implemented exactly as specified)

```
Original (BGR) → RGB → HSV → LAB → Gray → Gaussian → Median → Bilateral →
Global Threshold (Otsu) → Adaptive Threshold → Morphology → Canny Edges →
Contours → Bounding Box → [bonus: YOLO Ground Truth, bridges to Document 1]
```

For every step: image, shape, channel count, execution time, and a written
explanation — enforced by a single shared contract,
`src/opencv_fundamentals/schema.py:StepResult`, so the Visualizer never
needs to special-case which function produced a given result.

## Functions (one file each, matching the original spec exactly)

| Function | File | Produces |
|---|---|---|
| Image Reader | `image_reader.py` | Original (BGR) |
| Color Converter | `color_converter.py` | RGB, HSV, LAB, Grayscale |
| Blur Processor | `blur_processor.py` | Gaussian, Median, Bilateral |
| Threshold Processor | `threshold_processor.py` | Global Threshold (Otsu), Adaptive Threshold, Morphology |
| Edge Detector | `edge_detector.py` | Canny Edges |
| Contour Detector | `contour_detector.py` | Contours, Bounding Box |
| Visualizer | `visualizer.py` | Step grid PNG, per-step PNGs, timing table |

`main.py` orchestrates all seven in order, then adds one extra step outside
the original spec: overlaying the dataset's real YOLO ground-truth label
(via Document 1's `annotation_parser`) on the same image, so the
contour-based bounding box can be compared directly against what a human
annotator (and eventually, Document 6's trained model) actually labeled.

## Real findings from running this on actual dataset images

**Sample used: `000150.jpg`** (a red dress, train split) — chosen
deliberately over the first image tried (`000060.jpg`, a black/white
striped outfit) because the BGR/RGB channel swap is the whole point of this
document and is **only visible on saturated colors**. On the black/white
image, "Original (BGR)" and "RGB" look almost identical; on the red dress,
the dress renders **blue** in the deliberately-uncorrected BGR panel and
**red** in the RGB panel — same pixels, channel order is the only
difference.

**Timing — one real surprise, verified before writing it down:** the first
`cv2.cvtColor(..., COLOR_BGR2LAB)` call in a fresh process took **~102ms**,
roughly 100x every other color conversion (HSV took 0.3–0.5ms). Repeating
the LAB call 4 times in the same process gave `111ms, 0.29ms, 0.27ms,
0.25ms` — confirmed this is OpenCV building an internal LAB lookup table
**once per process**, not a real per-call algorithmic cost. Lesson kept in
the docstring and the notebook: never trust a single timing measurement: repeat it.

**Adaptive threshold vs. Otsu, on real e-commerce/selfie photos:** Adaptive
threshold keeps far more background texture (visible noise from tiled
floors, curtains, mirror edges) than global Otsu, because it reacts to
*local* contrast that a single global cutoff ignores. Morphological
close→open removes much of that speckle but not all of it — visible
directly in the "Morphology" panel of the saved grid.

**Classical contours are a poor detector on real photos.** On both sample
images, thresholding + contours found either one giant noisy blob (the
person silhouette merged with background shadow) or a dozen tiny
text-fragment contours (from a price-tag/logo in the background) — nothing
resembling "a garment." This is real, observed evidence for *why* Document
6 trains a learned model instead of relying on classical thresholding:
compare the "Bounding Boxes" panel (contour-based, often wraps the whole
person or nothing useful) against "YOLO Ground Truth" (the actual labeled
garment) in the same grid.

## Validated facts (not assumptions)

- All 7 functions run without error on real dataset images (sizes ranging
  624×468 to 968×750, both tested).
- `matplotlib.use("Agg")` must never be called inside a library module that
  a notebook also imports — it silently breaks the notebook's inline
  rendering with zero errors and zero embedded images, the least debuggable
  kind of failure. Fixed by moving the Agg call into `main.py`'s
  `if __name__ == "__main__":` guard, so it only fires for a real CLI run.
- Both CLI (`python -m src.opencv_fundamentals.main`) and notebook
  (`jupyter nbconvert --execute`) paths produce identical pipeline results
  from the same underlying functions — verified by running both against the
  same sample stem.
